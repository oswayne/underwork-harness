# Agent Note: UICP 用户身份与按用户隔离

Status: implemented

[English](2026-08-22-uicp-user-identity.md) | 中文

## 问题

Web 应用以单实例服务端向团队开放，多个用户携带不同平台 JWT 进入。预览沙盒已按凭据隔离，但服务端没有用户身份：会话与工作区全局可见，也没有任何界面能展示当前用户。

## 决定

团队确认了多用户设计（IMPLEMENTATION.md §15，M5）：

- **隔离粒度**：方案 A（客户端/UI 层）——每个用户只看到自己的工作区与会话，侧栏列表按归属过滤。服务端强制隔离列为可选硬化（P3），因为它需要 fork 上游 api-proxy。
- **应用包**：所有用户可见、无权限限制；每个用户的工作内容各自不同。进入工作区时先打本地快照，再拉取平台最新状态作为会话上下文（P1），避免用户互相覆盖。
- **用户信息持久化**：独立追加式 JSONL（`$DSH_HOME/uicp-users/users.jsonl`），按用户 id upsert 并压缩，保留原始自检载荷供后续展示。

P0 已交付 `packages/uicp/user-identity`：host 插件用 JWT 调 `/user/user/self` 校验，按凭据缓存（TTL 5 分钟，以 Token 哈希为键），持久化用户记录，并回答 `GET /uicp/user/me`。P1（归属记录 + 客户端过滤 + 进入同步）与 P2（用户展示）随后实施。

## 备选方案

- **服务端强制隔离（方案 B）**——延后：需要替换或修补上游 api-proxy 的 RPC 分发，扩大合并面；UI 层隔离当前足以覆盖团队部署。
- **复用 `dsh-storage-json` 保存用户记录**——已拒绝：独立 JSONL 让用户台账自包含、追加式且便于检查。
- **按用户划分应用包目录**——已拒绝：团队模型保持应用包共享；隔离作用于会话/工作区可见性与沙盒状态，而非包文件。

## 后果

身份 seam 是增量插件，全部落在 fork 自有包，上游合并保持无冲突；唯一的机械共享改动是新增 `tsconfig.host.json` 工程引用。新增 workspace 包后需在可联网机器上重新生成 `pnpm-lock.yaml`（本会话无法访问私有 registry）。P1 与 P2 仍待实施。
